# Image dataset: изображения и разметка

Узел **Import data → Image dataset** загружает картинки вместе с метками. Каждая метка привязана к пути файла, поэтому порядок строк таблицы и порядок файлов не требуется выравнивать вручную.

## Вариант 1: папки классов

```text
dataset/
  cat/
    first.png
    nested/second.jpg
  dog/
    first.png
```

Выберите `dataset` как корневую папку. Название её непосредственной подпапки задаёт класс; вложенные папки внутри класса разрешены. Одинаковые имена файлов в разных папках допустимы. Картинки прямо в корне требуют CSV-разметки.

## Вариант 2: изображения и CSV

```text
dataset/
  images/
    1.png
    10.png
    2.png
  metadata.csv
```

```csv
file_name,label,source_id
images/2.png,7,2
images/1.png,3,1
images/10.png,0,10
```

Корневой `metadata.csv` обнаруживается автоматически. Для другой таблицы укажите CSV, разделитель, столбец пути и столбец метки в настройках узла. CSV должен иметь заголовок и кодировку UTF-8 (BOM допускается). По умолчанию используются запятая, `file_name` и `label`.

Пути считаются относительно каталога CSV. Таблица и все изображения должны находиться внутри выбранного корня. Дополнительные столбцы сохраняются в метаданных образца. CSV определяет состав набора: картинки вне таблицы пропускаются с предупреждением. Неверный CSV приводит к ошибке.

## Настройки и подключения

- `X` – `float32`, форма `(N, H, W, C)`; `y` – `int64`, форма `(N,)`. Подключите их к `Fit model.x` и `Fit model.y`.
- `shape` – `(H, W, C)` без размера выборки; подключите к `Input.shape`.
- `class_names` – список названий классов в порядке их числовых кодов. По умолчанию названия сортируются лексикографически, поэтому, например, `10` предшествует `2`.
- Для тестового набора соедините `class_names` обучающего узла со входом `classes` тестового. Отсутствующие в тесте классы сохраняют свои коды; неизвестные метки вызывают ошибку.
- По умолчанию RGB, исходный размер, без нормализации. Grayscale сохраняет одну ось канала: `(N, H, W, 1)`.
- Размер задаётся как `(H, W)`; `(0, 0)` сохраняет исходный. Два положительных числа включают билинейное масштабирование без обрезки. Если размер не задан, все изображения должны быть одинакового размера.
- Просмотр показывает картинку, относительный путь, исходную метку и код класса. Миниатюра не изменяет данные `X`.
- Маленькие изображения увеличиваются для просмотра. Для значений вне диапазона 0–255 или дробного диапазона 0–1 предпросмотр масштабирует только отображаемую копию и явно показывает исходный диапазон.

Метки являются индексами классов. Для обычной классификации используйте `sparse_categorical_crossentropy` и выход модели с числом элементов, равным числу классов. Если модели нужны one-hot метки, примените существующий узел преобразования. Нормализацию выполняйте явно: загрузчик не делит пиксели на 255.

Поддерживаются JPEG, PNG, BMP, TIFF и WebP; многокадровые файлы (вроде GIF) отклоняются. Отсутствующие или повреждённые файлы, повторный путь, пустая метка, пустой набор и несовместимые размеры останавливают загрузку с диагностикой. Повторная неуспешная загрузка очищает предыдущие выходы узла. Служебные файлы игнорируются.

## Воспроизводимая проверка MNIST

Из корня репозитория, используя окружение с зависимостями проекта:

```sh
.venv/bin/python scripts/prepare_mnist_images.py
.venv/bin/python scripts/verify_mnist_images.py
```

Скрипты также работают по абсолютному пути из другого рабочего каталога. По умолчанию данные сохраняются в `.cache/mnist-images` относительно репозитория; `--root /path/to/dataset` позволяет задать другую папку.

!!! Возможная проблема на macOS. Если установленный Python на не видит системные корневые сертификаты и сообщает `CERTIFICATE_VERIFY_FAILED`, передайте существующий системный набор: `SSL_CERT_FILE=/etc/ssl/cert.pem .venv/bin/python scripts/prepare_mnist_images.py`. Проверка TLS при этом остаётся включённой.

Подготовка скачивает архив [из источника Keras](https://github.com/keras-team/keras/blob/master/keras/src/datasets/mnist.py), проверяет SHA-256 `731c5ac602752760c8e48fbffcf8c3b850d9dc2a2aedcf2cc48468fc17b673d1`. Обучающая и тестовая части остаются отдельными: 60 000 и 10 000 изображений.

```text
.cache/mnist-images/
  mnist.npz
  train/images/...
  train/metadata.csv
  test/images/...
  test/metadata.csv
  folders-train/0/...                 # по 5 картинок каждого класса 0–9
  folders-test-missing-class/0/...    # по 5 картинок классов 0–8
  verification.json                 # появляется после успешной сверки
```

Проверка заново читает PNG и CSV через загрузчик GraphNet, затем сверяет пиксели и метки **всех 70 000 изображений** с проверенным архивом по `source_id`. Также проверяются формы, типы массивов, сортировка записей, вариант папок классов и сохранение общего словаря при отсутствии класса в тестовой части. Успешный JSON-отчёт создаётся только после завершения всех проверок; путь можно задать через `--report`.

В приложении выберите папку `train`, включите grayscale, оставьте размер `(0, 0)`. Для тестового узла выберите `test` и подключите общий словарь классов. Для проверки второго формата используйте `folders-train` и `folders-test-missing-class`.

Проверка реального графа с одной эпохой обучения на 1 000 PNG, предпросмотром и освобождением диалогов/текстуры требует рабочего стола:

```sh
.venv/bin/python scripts/check_image_dataset_graph.py
```

Чтобы осмотреть граф и переключить образцы вручную, добавьте `--interactive`, затем закройте окно приложения для завершения проверки. Сценарий записывает `.cache/mnist-images/graph-validation.json`; другую папку данных можно указать через `--dataset`.

Подготовка может повторно записать собственные данные в папке с маркером `.graphnet-mnist-images.json`; чужую непустую папку она отклоняет. Данные и отчёты в `.cache` не попадают в Git.

## Контракт Python и ограничения

```python
from Src.image_dataset import load_image_dataset

train = load_image_dataset("dataset/train", color_mode="grayscale")
test = load_image_dataset(
    "dataset/test", color_mode="grayscale", class_names=train.class_names
)
assert train.class_names[train.y[0]] == train.samples[0].label
```

Результат содержит `X`, `y`, `shape`, `samples`, `class_names`, `warnings`. У образца есть `relative_path`, `label`, `metadata`. Записи сортируются по относительному пути, а массивы формируются совместно из этих записей.

!!! Ограничения. Первая версия предназначена для одного класса на изображение. Нет автоматического train/test-разбиения, импорта COCO/YOLO, рамок объектов или масок сегментации. Массив загружается целиком в память. Проверка обеспечивает техническое соответствие разметке, но не распознаёт ошибочную смысловую метку, например цифру 7, подписанную как 3.

Организация файлов вдохновлена и соответствует распространённым подходам [Torchvision ImageFolder](https://docs.pytorch.org/vision/stable/generated/torchvision.datasets.ImageFolder.html) и [Hugging Face ImageFolder](https://huggingface.co/docs/datasets/image_dataset); эти библиотеки НЕ нужны для работы узла, это просто пример.

## Проверка на других датасетах

Проверены оригинальные JPEG из [Hymenoptera, PyTorch](https://docs.pytorch.org/tutorials/beginner/transfer_learning_tutorial.html) (244 train + 153 val) и [Flowers, TensorFlow](https://www.tensorflow.org/tutorials/images/classification) (3 670 изображений, пять классов). Для разных исходных размеров задаётся RGB и `(64, 64)`; каждый элемент массива сверяется с независимым чтением и билинейным масштабированием исходного файла, метка – с папкой класса.

В Hymenoptera проверяется CSV в подпапке `annotations`: UTF-8 BOM, разделитель `;`, столбцы `path,target,origin`, пути относительно CSV, перемешивание с seed 913. Массивы, метки и пути должны полностью совпасть с вариантом папок классов. Проверяются дополнительные метаданные, ошибка отсутствующего файла и необходимость общего размера.

Для повторения выделите папку только под проверочные данные; сценарий повторно распаковывает архивы и записывает собственные CSV. Из корня проекта:

```sh
mkdir -p .cache/image-dataset-report/datasets .cache/image-dataset-report/flowers
curl --fail --location https://download.pytorch.org/tutorial/hymenoptera_data.zip \
  -o .cache/image-dataset-report/datasets/hymenoptera_data.zip
curl --fail --location https://storage.googleapis.com/download.tensorflow.org/example_images/flower_photos.tgz \
  -o .cache/image-dataset-report/flowers/flower_photos.tgz
.venv/bin/python scripts/verify_other_image_datasets.py
```

SHA-256 Flowers проверяется по [опубликованной сумме TFDS](https://raw.githubusercontent.com/tensorflow/datasets/master/tensorflow_datasets/datasets/tf_flowers/checksums.tsv).
Итоговый отчёт: `.cache/image-dataset-report/evidence/other-datasets-repro.json`. Аргумент `--root` меняет корень проверочных данных.

В интерфейсе для Hymenoptera выбирайте непосредственно `hymenoptera_data/train` или `val`: выбор общего родителя сделал бы названия `train` и `val` классами. Для Flowers выбирайте `flower_photos`. Это общий загрузчик папок и CSV, поэтому его код для этих датасетов не меняется.
